# 03 · 标注规范与验收标准

配套：[01-采集方案设计](01-采集方案设计.md)、[02-采集SOP与判定标准](02-采集SOP与判定标准.md)。
本文规定 VLA 数据的**语言指令（L）与结果位**怎么标、谁来复核、达到什么标准才算验收通过。

## 1. 标注对象与字段

| 标注对象 | 平台字段 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 语言指令 | `annotations.task_text` | ✅ | 一条 episode 一条祈使句；导出时写进 `tasks.jsonl` 并落到 `task_index` |
| 成功 / 失败 | `annotations.success` | ✅ | 0/1；导出时写进**末帧** `next.success`，并同步末帧 `next.reward`（1.0/0.0） |
| 备注 | `annotations.note` | ⭕ | 边界案例编号（`B1`…`B10`）、异常说明 |
| 标注员 | `annotations.annotator` | ✅ | 与复核员必须是不同人 |
| 复核标签 | `annotation_reviews.*` | 抽检必填 | 盲标：复核时看不到主标结果 |

> **注意语义**：成功位是**episode 级结论**，平台按 LeRobot 惯例写在末帧。
> 不要把它当成"逐帧奖励"来标。

## 2. 语言指令撰写规范

**模板**：`<动作> <物体> 到 <目标位置>`

| 槽位 | 允许取值（用词表，扩展需评审） |
| --- | --- |
| 动作 | 抓取 / 插入 / 放置 / 按压 / 推动 |
| 物体 | 红色连接器 / 蓝色连接器 / 齿轮 / 垫片 / 螺丝 / 纸箱 / 托盘 |
| 目标位置 | 左侧插槽 / 右侧料盒 / 工作台中心 / 料盒 A / 料盒 B |

**示例**：

| 正例 | 反例 | 问题 |
| --- | --- | --- |
| 抓取红色连接器并插入左侧插槽 | 小心地把那个东西放到合适的地方 | 主观副词 + 指代不明 + 槽位缺失 |
| 抓取齿轮并放置到料盒 A | 把齿轮放到料盒A（跟上次一样） | 引用上下文；大小写/空格需归一 |
| 推动纸箱到工作台中心 | push the box | 语言不一致（本项目统一中文指令） |

**硬性规则**：
1. 一条 episode 只描述**一个**任务目标；多目标必须拆 episode。
2. 禁止不可观测副词（小心地、轻轻地、稳稳地）与主观词（正确的、合适的、大概）。
3. 禁止指代（它、那个、这里）；物体与位置必须来自用词表。
4. 指令必须与观测一致：视觉里是蓝色就不能写红色（对应 SOP 边界案例 `B2`）。
5. 同一物体/位置在全库必须用**同一个词**（用词表约束）；平台比较一致性时会做
   `lower + 折叠空白` 归一，但**不**做同义词合并——同义词 = 不一致。

## 3. 成功位标注规范

直接采用 [02 文档第 4 节](02-采集SOP与判定标准.md) 的判定表，标注员**不得自行放宽**：

| 情形 | 标注值 | 备注要求 |
| --- | --- | --- |
| 抓取稳定、搬运无碰撞、放置到位、正常复位 | `success = 1` | — |
| 任一环节失败（掉落/放偏/空抓/急停） | `success = 0` | 写清失败环节 |
| B1 中途掉落但最终放对 | `success = 0` | 备注 `B1` |
| B5 空手放到位置 | `success = 0` | 备注 `B5` |
| B6 环境异常导致失败 | `success = 0` | 备注 `B6` |
| B2/B3/B7/B8 无效采集 | 不标注，转重采 | 备注 `B2` 等 |

**疑难不硬标**：拿不准时在 `/reviews` 里提争议，由裁决人拍板，**不要猜**。

## 4. 标注流程与工具

```
采集入库(v1)
   ↓  /annotation   主标：写指令 + 成功位 + 备注（采集员）
   ↓  /reviews      抽检：生成批次 → 盲标复核（复核员，另一人）
   ↓  /reviews      一致性：一致率 / Kappa / 文本一致率
   ↓  /reviews      争议裁决：采纳主标 / 采纳复核 / 自定义 → 写回主标注
   ↓  /export       导出（标注写进 tasks.jsonl 与 next.success）
```

抽检抽样是**可复现**的：按 `sha256(dataset:episode:salt)` 排序取前 N 条。
同一 `salt` 反复抽结果一致（便于复核员分头作业），换 `salt` 即换一批（下一轮）。

## 5. 抽检与复核机制

| 项 | 规定 |
| --- | --- |
| 抽检比例 | 首轮 **≥ 20%**；Kappa 稳定达标后每轮 **≥ 10%** |
| 抽检频次 | 每 500 条标注至少一轮；每批数据集发布前必须有一轮 |
| 单轮样本量 | **≥ 30 条**（< 30 条时 Kappa 的置信区间过宽，结论只作参考） |
| 盲标 | 复核界面**不展示**主标结果（平台已保证接口不返回主标字段） |
| 复核员 | 与主标人不同；同一批尽量只有一位复核员，便于计算一致性 |
| 轮次隔离 | 每轮用不同 `salt`，互不重叠 |

> **样本量提醒**：本机夹具数据集只有 5 条，其上算出的 Kappa 仅用于验证算法正确性，
> **不足以**作为验收依据。真实验收请在 ≥ 30 条的批次上算。

## 6. 一致性与验收标准

| 指标 | 验收线 | 优秀 | 平台口径 |
| --- | --- | --- | --- |
| 标注覆盖率 | **100%**（每条 episode 都有指令 + 成功位） | — | `/api/reviews/summary` 的 `annotated` |
| Cohen's Kappa（成功位） | **≥ 0.6**（高度一致） | ≥ 0.8（几乎完全一致） | `/reviews` 面板；分档见 `core/reviews.py` |

> **置信区间（不看点估计的裸数字）**：平台同时给出 Kappa 的 **bootstrap 95% 置信区间**
> （2000 次重采样、固定随机种子 —— 同一份数据每次得到完全相同的区间，可以直接写进报告）。
> 区间**跨过 0** 意味着"这两组标注的一致性并不比随机好"，此时点估计再高也不能算达标；
> 样本量 < 30 时平台会在面板上标出「仅作参考」。
| 指令文本一致率 | **≥ 0.9** | ≥ 0.95 | 归一后逐条相等比例 |
| 争议裁决完成率 | **100%**（`unresolved = 0`） | — | 争议队列「待裁决」为 0 |
| 抽检覆盖 | 每轮 ≥ 10% 且累计覆盖每个场景格 | — | `review_batches` |
| 质检 | 数据集 **0 error** | — | `/qc` |

**Kappa 分档与处置**（与代码一致）：

| Kappa | 含义 | 处置 |
| --- | --- | --- |
| ≥ 0.8 | 几乎完全一致 | 通过，可发布 |
| ≥ 0.6 | 高度一致 | 通过（验收线） |
| ≥ 0.4 | 中等一致 | 有条件通过：针对争议类别补培训后重抽 |
| ≥ 0.2 | 一般一致 | 不通过：修订本文档判定标准，重新标注争议样本 |
| < 0.2 | 一致性差 | 不通过：**暂停该场景采集与标注**，先重训标准与示例 |

## 7. 争议裁决

1. 成功位或指令文本不一致的 episode 自动进入**争议队列**；
2. 裁决人对照视频与 SOP 判定表，选择：`采纳主标` / `采纳复核` / `自定义`；
3. 裁决结果**写回主标注表**（`annotations`），复核记录标记 `resolved = 1`，备注写明理由；
4. 同一类争议连续出现 ≥ 3 次 → 视为**规范缺陷**，必须修订本文档（而不是逐条裁决了事）。

## 8. 与平台的对应关系

| 规范条目 | 平台实现 | 接口 / 页面 |
| --- | --- | --- |
| 指令 + 成功位标注 | `annotations` 表 | `/annotation`、`PUT /api/annotations/{dataset_id}/{episode_index}` |
| 指令写进导出物 | `tasks.jsonl` + `task_index` | `/export`（`core/lerobot.py::export_subset`） |
| 成功位写进导出物 | 末帧 `next.success` / `next.reward` | 同上 |

| 盲标复核 | `annotation_reviews` 表 | `GET /api/reviews/queue`、`PUT /api/reviews/{dataset_id}/{episode_index}` |
| 一致性指标 | `core/reviews.py::agreement` | `GET /api/reviews/agreement` |
| 争议裁决 | 写回 `annotations` | `POST /api/reviews/{dataset_id}/{episode_index}/resolve` |

## 10. 画布类标注（目标框 / 关键点 / 阶段切分）

语言指令与成功位是 episode 级的；**空间与阶段**信息要另外标。平台在 `/annotation` 提供了画布：

| 类型 | 画法 | 存什么 | 典型用途 |
| --- | --- | --- | --- |
| `bbox` 目标框 | 在帧上拖拽 | 归一化 `xywh`（0~1，左上角原点）+ 帧号 | 抓取目标、插槽位置 |
| `keypoint` 关键点 | 在帧上点一下 | 归一化 `xy` + 可选 `visibility` + 帧号 | 孔位中心、接触点 |
| `phase` 阶段 | 填起止帧 | `start` / `end`（帧号） | 接近 / 夹取 / 移动 / 放置 分段 |

**坐标一律归一化**（0~1），与分辨率无关 —— 换相机、换分辨率都不用重标。

**准入校验（服务端强制，不是靠标注员自觉）**：

- 框：宽高必须为正；左上角在 0~1；`x+w ≤ 1`、`y+h ≤ 1`（越界直接拒）
- 关键点：`x`、`y` 在 0~1；`visibility` 若给则必须在 0~1
- 阶段：`start < end`，且 `end ≤ episode 帧数`
- 帧号必须在 `0 ~ 帧数-1` 之间
- **`label` 必填**（没有名字的标注在后处理里无法统计）

**落在哪里**：平台库 `spatial_annotations` 表（权威记录），导出时写进交付包的
`meta/annotations.json`。**LeRobot v2.1 契约里没有承载空间标注的字段**，所以平台
**不改 `info.json` 的 features** —— 不伪造一个不存在的契约，而是明确标注这是平台约定。

## 11. 标注账号与工时

**这不是认证系统**（平台登录仍是 demo 级）。它解决两件实际的事：

### 花名册

`annotators` 表登记人名与角色（标注员 / 复核员 / 管理员）。历史记录里的自由字符串
（`annotations.annotator`、`annotation_reviews.reviewer`、`spatial_annotations.annotator`）
会被**自动补登**进花名册，既有人名不会被抛弃；未登记/已停用的人在统计里会被标出来。

### 工时

- 标注员在 `/annotation` 点「上工」→ 干活 → 点「收工」；
- 平台记录区间，并把**区间内真实发生的标注操作数从审计日志里数出来**（`audit_log.actor`），
  **不靠人填**；
- 没点「收工」的会话**不计入工时**，单独标出（宁可显示"有一个未结束的会话"，也不虚报时长）；
- 会话不足 1 分钟时不给"条/小时"，显示"样本太短"而不是编一个数出来。

校验：重复上工/重复收工被拒；已停用的人不能上工；角色必须是三者之一。
