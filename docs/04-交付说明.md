## 4. 真实数据上发现的真问题（不是模拟）

1. **所有数据集的 `info.json` 里 splits 都是 `0:N`** —— 训练与评估没有隔离，评估结果不可复现。已补可复现划分。
2. **`#1 pusht-real` 族与 `#2 pusht-broken` 族共享 5~6 条完全相同的 episode，血缘上互不相关** ——
   同时用于训练/评估会造成数据泄漏（本机是夹具造成，但检测器抓出它正是它该做的）。
3. **重复是"内容相同、文件字节不同"** —— 按文件哈希会全部漏报，所以指纹按取值算。
4. **`checkpoints/last` 是断链符号链接** —— `Path.rglob` 直接抛异常，平台改为健壮遍历。
5. **数据集可能位于只读/工作区外**（如 HuggingFace 缓存）—— 元数据写入改成"尽力而为 + 如实告警"，权威记录放平台库。
6. **`pyrealsense2` 其实在 base 环境可用（2.58.2）**，缺的是**硬件**不是 SDK（我早期说"两个环境都没装"是错的，已在文档更正）。

## 5. 剩下的限制（如实清单）

- **真机未接**：设备不在机（探测实测：相机 0 / 串口 0 / RealSense SDK 可用但设备 0）。
  采集软件链路已用真实视频帧回放验证；机械臂侧 `run_realtime()` 的 `read_joints()` 是留好的钩子，
  需要在实际设备环境里接 RealMan SDK（参考 `dhz\realman_ctrl.py`）。
- **推理服务需单独启动**（另一个 Python 环境）。
- **策略在环评估未做**：`/training` 的离线指标读的是 LeRobot 自己产出的 `eval_info.json`（真实文件），平台不会自己跑策略 rollout。
- **画布标注**只支持矩形框（无掩模/多边形），且**没有逐帧追踪**；坐标归一化存库。
- **数据划分与画布标注**是平台约定（`meta/splits.json` / `meta/annotations.json`）——
  LeRobot v2.1 契约里没有这些字段，所以**没有**改 `info.json` 的 features（不伪造契约）。
- **账号不是认证系统**：登录仍是 demo 级，花名册只解决"谁标了什么、花了多久"。
- **Kappa 只有点估计 + bootstrap CI**，样本量 < 30 时只作参考（平台会标出来）。
- **重复检测只到内容/采样级**，做不到语义级（"两条轨迹很像但不一样"）；且只报告不自动删。
- **存储清理需人工触发**（已有可选自动策略，**默认关闭**，避免无人值守误删）。
- **场景矩阵的格子级统计**（场景×对象）仍需人工汇总；`/scenes` 只到任务级。
- **争议只支持二方 + 第三方裁决**，不支持多复核员投票。

## 6. 接真机要做的三件事

1. 插上相机（RealSense，建议 USB3）。`/robots` 点「现在探测一次」应看到相机与 SDK 设备数 > 0。
2. 在 `tools/collect_client.py` 的 `run_realtime()` 里把 `read_joints()` 接上你们的 RealMan SDK 调用（位置已留好，调用时会明确报错提示）。
3. 跑一条真机采集：

```powershell
python tools/collect_client.py realtime --dataset realman7-grasp `
    --task "抓取红色连接器并插入左侧插槽" --seconds 6 --success
```

提交时会自动落成 LeRobot episode、登记版本（kind=collect）、并做时间同步体检。
