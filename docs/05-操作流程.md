## 1. 采集接入（`/collect`）

### 1A. 接入已有数据（最常用）

| 步骤 | 操作 | 判据 |
| --- | --- | --- |
| 1 | 点「扫描」 | 列出目录下发现的 LeRobot 数据集（显示 robot_type / 条数 / 帧数 / fps） |
| 2 | 对目标点「接入」 | 生成任务，进度条走完 → 「已接入的数据集」出现该数据集，带版本号 v1 与内容哈希 |
| 3 | 若是原始轨迹（`timestamp + joint_1..7` 的 parquet）→ 点「原始轨迹转换」 | 转成 LeRobot v2.1（`observation.state[7]` / `action[7]`），再走一次接入 |

等价命令：`POST /api/jobs/ingest {"path": "...", "name": "...", "with_video": true}`

**注意**：原始数据集**只读**（平台不改数据源）；标注、划分、质检结果都存在平台库里。若数据源在工作区外（如 HuggingFace 缓存），元数据写入会被拒并**如实告警**，不影响平台内使用。

### 1B. 真机实时采集

| 步骤 | 操作 |
| --- | --- |
| 0 | 先去 `/robots` 点「现在探测一次」，确认相机/串口/SDK 认到了 |
| 1 | 在机器人主机上跑客户端（真机）或回放（无硬件时验证链路） |
| 2 | 平台 `/collect` 的「实时采集会话」会实时显示帧数、状态 |
| 3 | 采集完由客户端提交，或页面点「提交为 episode」并选成功/失败 |
| 4 | 提交瞬间：落成真实 episode（含 mp4 编码）+ 自动接入平台（版本 kind=collect）+ 时间同步体检 |

```powershell
# 真机（需先接好 read_joints()）
python tools/collect_client.py realtime --dataset realman7-grasp `
    --task "抓取红色连接器并插入左侧插槽" --seconds 6 --success
# 回放（不需要硬件，验证链路）
python tools/collect_client.py replay --dataset collect-replay `
    --task "推动 T 形块到 T 形目标上" --success `
    --from "C:\Users\ll\Desktop\VLA\lerobot\.hf_cache\lerobot\lerobot\pusht" --episode 0
```

**时间同步判据**：提交结果里的 `步长偏差 ≤ 0.2`（超了会在质检里被「时间戳步长」规则**告警**，需要走修正类预处理，不会直接打回）。

## 2. 数据管理（`/data`）

- 看数据集清单（条数/帧数/版本/哈希/由来）、点进 episode 明细、预览视频（`/api/episodes/{ds}/{ep}/video`）
- **版本与血缘**：每个数据集的历史版本（kind = ingest / convert / preprocess / repair / export / collect / hard_set）+ 父子关系
- **跨数据集重复检测**（页面下方卡片）：点「看报告」→ 按内容指纹列重复组；点「重新扫描指纹」重算。
  判定分三档：`同数据集内重复` / `派生重复（同一血缘族）` / **`跨血缘族重复（需人工判断）`** —— 最后一档会给"若同时用于训练/评估会造成数据泄漏"的告警。

---

## 3. 数据预处理（`/preprocess`）

| 模式 | 做什么 | 产出 |
| --- | --- | --- |
| 预处理规则 | 按规则筛出通过的 episode（如 `qc_pass`） | 新数据集 + 版本（kind=preprocess，血缘指向源数据集） |
| **修正类预处理** | 7 个操作**真改帧**：`drop_broken` / `drop_dup_episodes` / `drop_invalid` / `dedup_ts` / `align_ts` / `resample` / `sync_video` | 新数据集 + 版本（kind=repair）+ 修复报告 |

**判据**：修复结果里会给出 `episodes_in → episodes_out`、`frames_dropped`、`videos_rebuilt`；**默认不造数据**（不插值补齐缺失帧、不伪造动作）。

---

## 4. 数据质检（`/qc`）

1. 选数据集 → 点「开始质检」→ 任务完成后看 **13 条规则**的通过/打回数与逐条问题（含实测值 vs 期望值）
2. 报告落盘到 `storage/reports/`，可在 `/data` 或导出页下载

**规则与严重级别（与代码一致）**：
  - **error（打回）**：文件完整性、空 episode、长度一致性、视频帧数一致性、视频可解码性、特征维度一致性、数值有效性（NaN/Inf）、**时间戳单调性**（时钟回退）
  - **warning（告警，需人工判断或走修正）**：时间戳步长偏差 > 0.2、帧率与声明差 > 0.1、动作有效性、语言指令完整性

**常见处置**：打回 → 去 `/preprocess` 做修正类预处理 → 再质检。

## 5. 数据标注（`/annotation`）

| 步骤 | 操作 |
| --- | --- |
| 0 | 顶部填**你的名字** → 点「上工」（工时开始记；做完点「收工」） |
| 1 | 选数据集 → 「加载」→ 逐条填**语言指令**、勾**成功位**、写备注 → 「保存」 |
| 2 | 需要空间/阶段信息 → 点该条的「画布」：拖拽画**目标框**、点击打**关键点**、填帧区间标**阶段** → 「保存标注」 |
| 3 | 右侧列表可逐条删除；下方「标注账号与工时」看工作量（工时/操作数/条每小时） |

**判据**：坐标一律**归一化 0~1**；越界、宽高非正、阶段起止反了、帧号超范围、**标签为空** —— 服务端一律拒掉并说明原因。
**工时口径**：区间内**真实操作数从审计日志数**（不靠人填）；没点「收工」的会话不计入工时，单独标出。

---

## 6. 标注抽检（`/reviews`）

1. 选数据集 → 设**抽检比例**（默认 10%，首轮建议 ≥20%）→ 「生成批次」（平台按 `sha256(dataset:episode:salt)` 抽样，**可复现**）
2. 复核员**盲标**（看不到主标注）→ 提交
3. 看一致性：**一致率 / Cohen's Kappa + bootstrap 95% CI / 文本一致率**，以及争议清单
4. 有争议 → 第三方**裁决**，结果写回主标注表

**验收线**：抽样覆盖率、Kappa ≥ 0.6 通过（≥0.8 优秀）、文本一致率 ≥ 0.9、争议裁决率 100%。
**注意**：配对样本 < 30 时 Kappa 与区间只作参考（平台会标 `reliable=false`）；**区间跨 0 说明一致性并不比随机好**，别只看点估计。

## 7. 数据集导出（`/export`）

| 步骤 | 操作 |
| --- | --- |
| 1 | **先做数据划分**（卡片「📐 数据划分」）：选数据集、salt、模式（`random` 可复现 / `ordered` 连续区间）、比例 → 「执行划分」 |
| 2 | 按划分导出：表格右侧「导出 train/val/test」 |
| 3 | 或按需导出：上方选导出模式 `all` / `qc_pass`，生成数据集包 |
| 4 | 产物列表里下载 zip |

**产出**：LeRobot v2.1 目录 + zip；导出时会把标注写进 `tasks.jsonl`、成功位写进 `next.success`/`next.reward`、画布标注写进 `meta/annotations.json`（平台约定）。

---

## 8. 模型训练与评估（`/training`）

| 步骤 | 操作 |
| --- | --- |
| 1 | 「扫描」训练产物目录（默认 `VLA\lerobot\lerobot_project\outputs`）→ 列出各 run 的 policy/数据集/steps/lr/seed 与日志指标点数 |
| 2 | 对目标点「登记」→ 生成实验台账：绑定**数据集版本 + 内容哈希 + 训练划分（split/salt）**，并给出**复现命令** |
| 3 | 看 loss 曲线与离线评估（`pc_success` / `avg_sum_reward` / 逐 episode 结果） |
| 4 | 「从质检/标注收集」bad case → 选数据集 → 「回灌为困难集」→ 产出困难集数据集（血缘 `badcase:return`） |

**判据**：`/api/training/compare/{dataset_id}` 会判断同一数据集上的多个实验**能不能直接比指标** —— 只有内容哈希与 split+salt 都相同才可比。

## 9. 运维与排查

| 页面 | 用途 |
| --- | --- |
| `/log` | **真实操作审计**（任务/版本/质检/标注/复核/采集/训练/划分/存储/工时），可按级别与模块筛选 |
| `/system` | 真实运行状态（存储用量、数据规模、推理服务 GPU、最近告警）+ **存储清理**（先算账→预览→执行；也可开自动策略，**默认关闭**） |
| `/scenes` | 按任务聚合覆盖度；**相似写法归一**（人工确认，不静默合并） |
| `/robots` | 按本体聚合 + **设备在环探测**（采集前必看） |
| `/models` | 真实权重清单 + 真实推理测试（GPU） |
| `/interfaces` | 对外推理接口登记展示 |

**存储清理安全边界**（写死在代码里）：只动 `storage/{exports,reports,sessions,testdata}`；**绝不碰 `storage/datasets`**；**不删任何被数据集登记引用的目录**；导出目录只在**同名 zip 已存在**时才算可回收。

## 11. 卡住了怎么办

| 现象 | 原因 / 处置 |
| --- | --- |
| 页面点按钮没反应 | 浏览器控制台看 `API is not defined`：`platform.js` 必须在页面内联脚本之前加载（已在 `base.html` 保证） |
| 数据集接入后 `/collect` 里看不到 | 扫描根目录未包含该路径；改用 `/data` 直接确认，或把路径加入扫描根 |
| 质检报「时间戳步长」 | 采集时抖动/丢帧 → `/preprocess` 用 `align_ts` / `resample` 修正 |
| 元数据写入被拒（PermissionError） | 数据源只读或在工作区外 —— **平台库仍是权威记录**，导出照常可用 |
| `/models` 显示推理服务未运行 | 用页面给出的命令在 `envs\yolov8n` 环境启动（base 的 torch 是坏的） |
| 任务一直 queued | 后台线程池忙或任务异常；到 `/log` 按级别=ERROR 看具体报错 |
| 提交采集会话报「步长偏差」大 | 客户端时钟不稳或采集丢帧；看 `/collect` 会话卡片的偏差值 |

## 12. 没有真机时怎么演练（仿真数据）

**能演练到什么程度**：除了"物理相机与机械臂"，整条链都是真的 —— 仿真器只替换
`read_joints()`（换成 7 轴抓放轨迹）与相机帧（换成 cv2 合成画面），**其余走同一个会话接口**
（归一化 → mp4 编码 → episode 落盘 → 平台接入 → 时间同步体检）。仿真数据任务文本带 `[仿真]` 前缀，不会与真机数据混淆。

### 采集

```powershell
# 4 条干净数据（3 成功 1 失败），10Hz × 6s，7 轴 + 160×120 图像
python tools/sim_collect.py --dataset sim-realman7-pickplace --episodes 4 --seconds 6 --fps 10

# 注入缺陷，用来看质检怎么打回、修复怎么救回来
python tools/sim_collect.py --dataset sim-broken --episodes 2 --seconds 4 --defect backwards@1
python tools/sim_collect.py --dataset sim-gap    --episodes 1 --seconds 4 --defect gap@0
```

`--defect` 支持 `backwards@索引`（时间戳回退 → 质检 **error** 打回）与 `gap@索引`（时间跳变 → **warning**）。
